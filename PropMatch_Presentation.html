Project Overview

Executive Summary: The PropMatch Solution

AI-driven property discovery combining RS candidate selection with RL reward optimization

1. The Challenge
Legacy Portal Failure
  • Rigid Boolean Filtering: Classical portals rely on strict SQL queries (price ≤ X, BHK = Y). When an exact match is missing, users face zero results.
  • Ignored Trade-offs: Buyers frequently compromise on balcony count or building age for prime locality, which Boolean engines cannot compute.
  • Tower Clutter: Massive projects list identical floorplans across floors, dominating search results.
2. The RLRS Formulation
Contextual Bandit Policy
  • Contextual User State: User preferences define a high-dimensional state vector across 11 constraints.
  • Continuous Reward in [0, 1]: Multi-factor reward model evaluates soft trade-offs instead of binary elimination.
  • Deep Neural Estimator: PyTorch deep value network scores 497-dimensional state-action pairs to guide top-k rankings.
3. The Deliverable
End-to-End Execution
  • Scale: 60,255 real properties preprocessed on HPC with 500,000 interaction samples.
  • Model Performance: Test R² = 0.9986, Test RMSE = 0.0083, NDCG@4 = 0.9994 (+41% over baseline).
  • Full Stack: Sub-80ms FastAPI inference microservice with a responsive React UI.

Problem Formulation

Why Real Estate Recommendation Requires Both RS & RL

Overcoming the limitations of traditional search engines in high-value multi-attribute domains

Limitations of Traditional Real Estate RS
  • The Binary Search Cliff: A listing priced Rs. 10,000 over budget or 15 sq.ft below min area is dropped completely, ignoring near-perfect properties.
  • No Weighted Trade-off Capability: Cannot quantify how much an additional bedroom compensates for a slightly longer commute.
  • Catalog Duplication: Prominent residential towers flood search result pages with identical unit sizes on different floors, destroying result diversity.
  • Extreme Cold Start: Property purchases are rare life events. Users do not possess extensive historical interaction matrices, rendering collaborative filtering ineffective.
The PropMatch RL + RS Solution
  • Continuous Suitability Metric: Maps complex multi-feature alignment into a bounded reward $r \in [0.0, 1.0]$, rewarding close compromises gracefully.
  • Multi-Dimensional Utility Function: Integrates 10 weighted attributes simultaneously (budget, locality, BHK, age, amenities) into a single scalar value.
  • Contextual Bandit Optimization: Treats user requirements as the context and listing retrieval as the action to maximize expected match satisfaction.
  • Project-Level Deduplication: Post-ranking algorithm eliminates tower-level duplicate listings, enforcing true visual variety in Top-4 results.

RS Strategy

Stratified Candidate Sampling & Balanced Reward Space

Eliminating exposure bias by constructing multi-tier candidate sets for each user

Why Not Pure Random or Greedy Sampling?

Sampling only top matches causes policy blindness on subtle trade-offs. Sampling purely at random yields >95% irrelevant pairs with near-zero rewards. PropMatch uses a 3-tier stratified sampling approach (50 candidates/user).

Tier 1: Strong Candidates
20 Listings / User (40%)
  • Exact locality match with price within budget_max and matching bedroom count.
  • Reward Range: Typically [0.80, 1.00].
  • Teaches the model to recognize ideal property choices.
Tier 2: Moderate Candidates
15 Listings / User (30%)
  • Matching city and general price band, but exhibiting minor deviations in locality or property age.
  • Reward Range: Typically [0.45, 0.75].
  • Enables learning nuanced soft trade-offs and secondary compromises.
Tier 3: Hard Negatives
15 Listings / User (30%)
  • Notable budget overage, area mismatch, or opposing property type.
  • Reward Range: Typically [0.10, 0.40].
  • Prevents positive-class skew and establishes firm lower bounds.

RS Ranking & UX

Top-K Selection & Project-Level Title Deduplication

Eliminating tower-level listing replication to deliver meaningful recommendation diversity

Deduplication Algorithm

Large residential complexes register multiple units differing only by minor floor area or price. A naive top-4 ranking causes one tower to occupy all 4 spots.

# Top-K Ranking with Project-Title Deduplication def deduplicate_top_k(candidates, scores, k=4): candidates["score"] = scores ranked = candidates.sort_values("score", ascending=False) seen_titles, top_k = set(), [] for _, row in ranked.iterrows(): title = row["title"].strip() if title not in seen_titles: seen_titles.add(title) top_k.append(row) if len(top_k) == k: break return top_k

RL Formulation

Property Matching as a Contextual Bandit

Formulating high-dimensional property discovery as a single-step decision process with contextual states

State / Context ($s$)
User Preference Vector
  • Budget Threshold: Max spending ceiling.
  • Area Interval: [min_area, max_area].
  • Room Allocations: Bedroom, bathroom, balcony preferences.
  • Geography: Targeted locality and city.
  • Structure: Property type, furnishing, and age tolerances.
Action Space ($a$)
Catalog Property Choice
  • Discrete Catalog Actions: Selecting a property listing from the 60,255 available listings.
  • Feature Cross-Product: Action joins property attributes with user context.
  • Policy Goal: Learn a value function $Q(s, a)$ such that selecting $\text{argmax}_a Q(s, a)$ maximizes user suitability.
Reward Signal ($r$)
Continuous Suitability Score
  • Bounded Range: Scalar score $r(s, a) \in [0.0, 1.0]$.
  • Simultaneous Criteria: Holistic evaluation across 10 distinct attribute match functions.
  • Bandit Feedback: Reward observed specifically for tested (context, action) pairs without delayed credit assignment.

Reward Engineering

The 10-Factor Multi-Component Reward Function

Mathematical formulation of property match suitability as a weighted convex combination

Reward Function Weights ($\sum w_i = 1.0$)
  • Budget Alignment (20%): Continuous decay based on price deviation vs budget.
  • Bedroom Count (15%): Exact match reward with progressive penalty for deviations.
  • Locality Match (15%): Strict geographic sub-district correspondence.
  • Area Range (12%): Penalty proportional to distance outside [min_area, max_area].
  • Bathroom Count (8%): Comparison against requested bathroom preference.
  • City Boundary (8%): Major municipal boundary verification (e.g. Mumbai).
  • Property Type (7%): Apartment vs Villa vs Independent Floor.
  • Furnishing Status (6%): Furnished vs Semi-Furnished vs Unfurnished.
  • Building Age (5%): Depreciation penalty for older properties.
  • Balcony Count (4%): Bonus alignment for requested balconies.
Mathematical Formulation & Statistics
# Convex Combination Suitability Function R(s, a) = ∑ (w_i × S_i(s, a)) where ∑ w_i = 1.0 Target Range: R(s, a) ∈ [0.0, 1.0]
Dataset Reward Distribution (500,000 Rows):
  • Minimum Observed: 0.0721 • Maximum: 1.0000
  • Mean Reward: 0.6873 (± 0.2205) • Median: 0.6616
  • Quartile Balance: 140,000 interactions in [0.9–1.0], 195,000 in [0.5–0.8], 55,000 in [0.2–0.4].
  • Sigmoid Compatibility: Perfectly aligns with the [0, 1] output range of the neural network.

Model Training

HPC Training Setup & Disjoint User Splitting

Strict partitioning by user ID prevents identity memorization and guarantees unbiased evaluation

User-Level Disjoint Splitting

Partitioned by unique User ID rather than random rows. A user seen during training never appears in validation or testing.

  • Training Set (80%): 8,000 unique users • 400,000 interaction rows.
  • Validation Set (10%): 1,000 unique users • 50,000 interaction rows.
  • Test Set (10%): 1,000 unique users • 50,000 interaction rows.
  • Disjointness Verification: Confirmed 0 user overlaps ($\text{Train} \cap \text{Val} = 0, \text{Train} \cap \text{Test} = 0, \text{Val} \cap \text{Test} = 0$).
Hardware & Early Stopping Dynamics
  • Compute Infrastructure: NVIDIA H100 PCIe MIG (3g.40gb partition).
  • Batch Size: 1,024 samples per step (391 batches/epoch on train).
  • Total Epochs Requested: 30 • Early Stopping Patience: 5 epochs.
  • Early Stopping Execution: Validation RMSE plateaued; training stopped at epoch 25 with optimal checkpoint saved at epoch 20.
  • Artifact Outputs: best_model.pth, model_config.json, training_history.json.

Critical Analysis

Synthetic Learning vs Online Bandit Feedback

Understanding the boundary between simulated reward fitting and real-world human preferences

Current Stage: Offline Synthetic Policy
  • Deterministic Target: In simulation, reward is an exact algebraic function of 22 features. $R^2 = 0.9986$ confirms the neural network successfully learned this non-linear mapping.
  • No Data Leakage: All preprocessing and user splits are strictly isolated. No test user was memorized.
  • The Generalization Nuance: Proves mathematical soundness, but human buyers exhibit latent subjective preferences (lighting, floor level, Vastu) not captured in synthetic formulas.
Next Phase: Online Bandit Fine-Tuning
  • Click / Selection Bandit Signal: Log user actions: $r = 1.0$ for selected/inquired properties, $r = 0.0$ for shown but unchosen properties.
  • Warm-Start Fine-Tuning: Utilize current best_model.pth as initialization; periodic fine-tuning ($\text{lr} = 10^{-4}$) avoids catastrophic forgetting.
  • Exploration Strategy: Incorporate $\epsilon$-greedy ($\epsilon = 0.10$) or Thompson Sampling (Gaussian noise injection) to prevent recommendation echo chambers.
